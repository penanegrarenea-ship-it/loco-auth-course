还没做的 notes 设计

下面不是已实现的接口。仓库里没有 notes 表，也没有 /api/notes。

新迁移，不改 users 的列
notes
  id          框架的 PkAuto
  user_id     非空，指向 users.id，不是 pid
  body        非空文本
  created_at / updated_at    create_table 会再加

POST /api/notes    要 Bearer
GET  /api/notes    只返回这个 user_id 的行

现有 JWT 只有 pid。处理请求时用 find_by_pid 找到 users.id，再写 notes.user_id。不要把 user_id 放进 claims，这样旧 JWT 仍然可用。

授权例子

正向：A 的 JWT 创建的笔记，A 再去列表里看得到，因为查询条件是 A 的 users.id。

反向：B 拿自己的有效 JWT 去要 A 的笔记，签名是对的，但 user_id 对不上，结果应是空列表或 404。这是授权，不是再做一次登录。当前应用没有这个判断，因为笔记还不存在。

已有的 /api/auth/*、/_health、/_ping、/_readiness、GET / 都不必改。
